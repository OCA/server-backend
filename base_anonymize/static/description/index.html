Anonymize a database

This module provides a flexible mechanism and default configuration for anonymizing data in an Odoo database.

Unlike odoo-bin obfuscate, which encrypts values with a password and can be reversed, the overwrite is irreversible: the result is anonymized, not pseudonymized, data.

Use Cases / Context

This module was developed because the OCA internal tools workgroup needs access to the OCA database, but shouldn’t have access to the data of OCA members.

It should be useful in any setting where external developers need access to a database, or for setting up test and staging instances from a copy of production.

Configuration

To configure this module, you need to:

  1. Go to Settings / Technical / Anonymization / Field Definitions
  2. Review fields to overwrite: every field can be overwritten by some method, and the overwritten records can be restricted by a domain

Domains are evaluated with two variables: protected_partner_ids, the partners of the companies, OdooBot and the public users, which the default definitions leave untouched, admin_user_ids, the superuser and the administrator, and protected_user_ids, the same plus the public users.

Methods that take options read them from the Options column, a JSON object overriding the defaults shown in Default options. The Pattern with record id method replaces {id} with the record’s id, so partner{id}@example.com gives every partner a distinct address that cannot receive mail.

Definitions for fields of modules that are not installed are kept and simply not applied. Recompute stored computed field definitions rebuild the stored copies of anonymized values (complete_name, email_normalized, …): give them a higher sequence than the fields they are computed from.

The definitions for the descriptions of invoice, sale and purchase lines are inactive by default: those descriptions often quote the customer, but replacing them makes the documents harder to read. Activate them (filter on Archived) to replace each description with the name of the line’s product, or with Line {id} on lines without product.

Usage

To use this module, you need to:

  1. Neutralize the database (odoo-bin neutralize, or a copy neutralized by the database manager or by Odoo.sh): the anonymization refuses to run on a database without the database.is_neutralized parameter, so that it cannot overwrite production data
  2. Go to Settings / Technical / Anonymization / Run Anonymization
  3. Confirm you really mean it

The above is only for testing configurations. Usually you would script this on a clone of the production database, before handing it over:

odoo-bin neutralize -d clone
odoo-bin shell -d clone <<'END'
env['ir.module.module'].search([('name', '=', 'base_anonymize')]).button_immediate_install()
env['anonymize.wizard'].action_run()
env.cr.commit()
END

then dump the database and copy the file store.

!!CAUTION!! The default configuration replaces the database secret and gives all users the same random password, stored in the system parameter base_anonymize.password. The administrator’s login becomes admin. If you run it from the user interface you will be logged out.

Known issues / Roadmap

  • add more anonymization methods to generate syntactically correct data like IBANs, VAT numbers, …
  • add definitions for all relevant OCA modules
  • anonymize the content of attachments other than those of partners, users, invoices, payments, sale orders and leads, which are dropped
